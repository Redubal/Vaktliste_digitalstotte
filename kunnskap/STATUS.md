Appen eier dataene; Excel var en engangsinnlasting (`npm run migrer` er kjørt). `npm run import` nekter å overskrive uten `--overskriv`, og en slik import fjerner Admin-endringer og `erAdministrator`. Excel-fila ligger i `app/` (ikke i git).
- Skriving går alltid gjennom `endreVaktliste` i `lib/lager.ts` (revisjon, sikkerhetskopi i `data/sikkerhetskopi/`, atomisk lagring). **Alle handlinger går gjennom `utforSom` i `lib/utfor.ts`**: Admin (`app/admin/handlinger.ts`, krav «administrator») og planen (`app/handlinger.ts`, krav «ansatt»). Hva en ansatt får gjøre sjekkes i `lib/domene.ts` (`kanEndreEndring`: egne som venter; `kanSletteEndring`: bare administrator), ikke bare i siden.
- **Endringsloggen** (`lib/endringslogg.ts`) skrives fra `endreVaktliste` til `data/endringslogg.jsonl` (ikke i git). Nye tabeller eller felt må inn i `TABELLER` og `FELTNAVN` der, ellers vises rå feltnavn. `endretAv` er oppsettets id; synk (Fase 30, parkert) trenger egen avsender (`TODO.md`).
- **Vedlikeholdsmodus:** `Vaktliste.innstillinger`. Rotlayouten `app/layout.tsx` skjuler alle sider for ikke-administratorer; «Velg deg selv» står igjen der. Handlingene i planen nekter også ansatte da.
- `lib/domene.ts` deles med skriptene og har ingen imports (skjemaversjon 12). Node 26.8.2 importerer `.ts` direkte; i `node`-skript på Windows må absolutte stier i `import` skrives som `file:///C:/...`.
- **Godkjenning, avvisning og innlegging:** `Status.virkning` er `godkjent|venter|avvist`; en endring uten status venter. Ingen velger status selv: ny endring fra ansatt får første status som betyr «venter», «Godkjenn» første «godkjent», «Avvis» første «avvist» (alfabetisk); mangler en, gir handlingen en feilmelding. «Avvis» (`avvisEndring`) bare for endringer som venter, lagrer `avvistGrunn`. Klikk på en dag åpner `components/EndringVindu.tsx` (`<dialog>`, hook `useEndringVindu`); ansatt legger inn bare for seg selv og får «venter», administrator for alle og får «godkjent». `page.tsx` sender `revisjon` og `valg` til alle som har valgt seg selv. `BehandleKnapper` (Godkjenn + Avvis) og `VenterPanel` (alle som venter, uansett uke og team; i Ukeplan og Måned) ligger i `components/Godkjenning.tsx`; knapper kun for administratorer. Er to endringer på samme dag, vinner den godkjente (`lib/ukeplan.ts`). Etter kodeendringer i `app/page.tsx` kan dev-serveren sende gamle data: start den på nytt (Ctrl+C, `npm run dev`).
- **«Rett» fra godkjenningslista (Fase 25):** `useRettVindu` i `EndringVindu.tsx` åpner samme `Vindu` direkte på en endring; `GodkjenningListe` (`components/GodkjenningListe.tsx`) setter lista (`VenterListe` med `onRett`) og vinduet sammen. En retting endrer ikke status.
- **Dager (Fase 26–27):** `/admin/dager` (`components/DagAdmin.tsx`), regler i `sjekkDag` (`lib/domene.ts`), handlinger `leggTilDag`/`endreDag`/`slettDag`. Måned viser teksten som `maaned-merknader` i `MaanedClient.tsx`; Ukeplan leser samme `dager`. `fri` på dagen gir «Fri» i cella via `beregnCelle` (`lib/ukeplan.ts`); egen endring vinner.
- **«Mine endringer» (Fase 24):** fanen `mine` i `app/page.tsx` bare når noen har valgt seg selv; `getMineEndringer(id)` i `lib/vaktlista.ts` er eneste sted `avvistGrunn` leses ut, så andres begrunnelser sendes ikke. Merket «Godkjent» gjelder bare egne (`egenGodkjent`, `lib/ukeplan.ts`).
